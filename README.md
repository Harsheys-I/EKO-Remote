# EKO Remote v1.2.0

EKO Remote is the static control website for the physical EKO Raspberry Pi robot. It can be
published on GitHub Pages and connects through either:

- Wi-Fi: private Tailscale HTTPS requests plus WSS telemetry.
- Bluetooth Low Energy: semantic requests through the included Pi bridge.

No robot token or cloud credential is compiled into the site.

## v1 control surface

| Area | Purpose |
| --- | --- |
| Normal right rail | Two live 128x64 eye previews, expression, gaze, face ID, OLED state, and sound angle |
| Debug Mode right rail | Live structured Pi logs with level filtering, pause, resume, clear, and workflow state |
| Dashboard | Pi telemetry, physical-module readiness, activity, and explicit motor lock |
| Drive | Keyboard, touch, and automatic Gamepad API input; locked until motor drivers are installed |
| AI & Voice | Categorizer, thinker, memory, Groq, wake-word phase, camera, song, and **EKO voice replies** control |
| Vision | Physical Pi-camera snapshot, face enrollment, active identity, and local person detection |
| Memory | Search, create, and delete user-scoped memories |
| House Map | Optical-mouse trail, MPU yaw, fused pose, and map reset |
| Logs | Runtime event history, filtering, pause, and JSON export |
| Config | Typed multi-file validation and atomic apply |
| Terminal | Optional authenticated Pi PTY over Tailscale WSS |
| Settings | Connection details and physical startup state |

Mock hardware is not part of EKO Remote v1.2.0. The top-bar **Debug mode** switch is available on
every page. It replaces the eye rail with the live structured records generated by the Pi.

The Live Eyes rail has no browser-only animation. It renders the last state successfully committed
to both physical OLEDs, so the site cannot run ahead of the real face.

On the AI page, **EKO voice replies** changes `voice_responses` live. AI answers always remain in
the website chat; when the switch is on and ElevenLabs is ready, the same answer is also spoken by
EKO.

## Gamepad

The Drive page automatically reads a controller already paired to the browser device. There is no
second software pairing button. The supplied mapping is:

| Input | Action |
| --- | --- |
| Axis 0 | Strafe |
| Axis 1 | Forward/back |
| Button 4 / L1 | Rotate left |
| Button 5 / R1 | Rotate right |

Because the v1 robot package deliberately has `hardware.motors.enabled: false`, Drive shows the
controller vector but does not send physical motion until the TB6612FNG hardware is installed and
accepted in a later release.

## Run locally

```bash
npm ci
npm test
npm run dev
```

Open `http://localhost:5174`.

## Publish to GitHub Pages

Overlay this release onto the existing Remote Git repository. Keep its `.git` directory:

```bash
rsync -a --delete \
  --exclude .git \
  --exclude node_modules \
  --exclude dist \
  /path/to/EKO-Remote_v1.2.0/ /path/to/your/EKO-Remote/

cd /path/to/your/EKO-Remote
npm ci
npm test
npm run build
git add -A
git commit -m "Release EKO Remote v1.2.0"
git push
```

Select **GitHub Actions** as the Pages source. The included workflow tests and builds before
deployment. See [Publish v1.2.0](docs/PUBLISH_1.2.0.md).

## Connect

GitHub Pages cannot call a plain HTTP robot API. On the Pi:

```bash
cd /home/pi/EKO
sudo ./deploy/setup_tailscale_https.sh
tailscale serve status
```

Enter the resulting address in Remote exactly like:

```text
https://eko.example-tailnet.ts.net
```

Do not add `:8765`. Enter the current `EKO_API_TOKEN` separately. The browser device must be signed
into the same Tailscale network.

The robot should keep:

```env
EKO_API_HOST=127.0.0.1
EKO_CORS_ORIGIN=https://YOUR-GITHUB-PAGES-ORIGIN
EKO_API_TOKEN=YOUR-ROTATED-TOKEN
EKO_LOG_LEVEL=DEBUG
```

## BLE fallback

Install the bridge on the Pi from this release:

```bash
sudo apt update
sudo apt install -y bluetooth bluez python3-venv
sudo systemctl enable --now bluetooth

cd /opt/eko-remote/bridge
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt

export EKO_API_URL=http://127.0.0.1:8765
export EKO_API_TOKEN='robot-api-token'
export EKO_BLE_TOKEN='separate-nearby-control-token'
.venv/bin/python eko_ble_bridge.py
```

The bridge carries incremental structured logs as well as status, events, AI commands, config,
vision, eyes, faces, mapping, and motor-stop operations. Camera images are chunked and slower over
BLE. The terminal remains Wi-Fi/WSS only.

## Security

- Keep the Pi API on loopback behind Tailscale Serve.
- Use different random values for `EKO_API_TOKEN` and `EKO_BLE_TOKEN`.
- Rotate any token or cloud key that has been pasted into chat or terminal output.
- Saved fallback Wi-Fi passwords remain write-only and Pi-local.
- Debug records can contain request text and errors; do not publish exported logs without review.
- The static bundle contains no `.env`, API key, token, Wi-Fi password, or robot database.
- Motor enablement remains a Pi configuration and wiring decision, never a browser-only switch.

See [Architecture](docs/ARCHITECTURE.md), [BLE protocol](docs/BLE_PROTOCOL.md), and
[GitHub Pages HTTPS](docs/GITHUB_PAGES_HTTPS.md).
